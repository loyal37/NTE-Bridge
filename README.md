# NTE Bridge / 异环桥接

Blender 4.5.7 LTS 与 Unreal Engine 5.6 的角色 Mod 制作桥接。独立项目，沿用 LoyalTools 的节点操作思路，使用 NTE 资产路径、FBX 和 UE 导入流程。

当前版本 **0.4.4，开发预览**：从解包角色文件夹识别资源和材质资料，一次点击完成当前模型导出与 UE 同步。角色蓝图可把分离的物体合并成一个骨骼网格，并用材质球与贴图节点新建材质实例。烘焙角色文件夹后，在 Blender 中浏览、勾选资产，导出所选文件并自动调用外部打包器。一个导入任务对应一个骨骼网格与其骨架。

## 当前可以做什么

- 角色配置和节点图随 `.blend` 保存；为每个材质槽保留独立的部件标识。同一材质可被多个槽引用。
- 读取解包目录的 JSON，识别网格、Skeleton、PhysicsAsset、材质槽，以及角色原游戏材质（制作流程中的“母材质球”）的贴图与参数。多个原网格可选择。
- 在临时副本中导出网格与骨架，保留形态键、UV 与权重；导出操作不保存原 Blender 工程。
- FBX 固定关闭动画和“添加叶骨”，几何平滑使用“面”；发送到 UE 时自动采用这组设置，无需手动打开 FBX 导出面板。
- 角色蓝图沿用 LoyalTools 的节点风格：`物体`、`材质球`、`贴图`、`物体切换`、`群组`、`生成` 六种节点，详见下文“角色蓝图”。
- 指定完整 `/Game/...` 路径，向准确匹配的 UE 工程发送 FBX，分配材质、Skeleton 和 PhysicsAsset。缺失的占位资产仅在开启对应选项后创建。
- UE 中主网格原有槽的可见名称与绑定材质同名；蓝图中其他物体的槽与 Blender 材质槽名完全相同。内部导入标识继续区分每个槽，共用材质的槽仍保持独立。
- 自动读取 Blender 材质连接的漫射图片，导入原游戏路径并连接到 UE 占位材质的基础颜色，方便预览。自动图片不会默认加入 Mod；烘焙后可在资产窗口中自行勾选。
- 导入替换贴图并设置用途：漫射 BC7+sRGB；ID/LightMap BC7 非 sRGB；法线 Normalmap/BC5 非 sRGB。
- 单独烘焙整个 UE 角色文件夹，包括后来在 UE 中新增、修改并保存的资产；默认当前角色，也可指定其他角色目录。在 Blender 资产选择窗口中搜索、筛选和勾选文件，导出后自动打包，验证 `.pak/.utoc/.ucas` 三个输出文件。

**本版尚未把 Blender 节点中的切换生成为 UE 运行逻辑。** 发送到 UE 后，物体切换节点会显示可直接粘贴到 HT 工具 `Material ID(s)` 的槽号串；在 UE 中用现有插件生成并保存蓝图后，再烘焙角色文件夹并勾选蓝图打包。后续版本会直接接入现有切换与面板生成器。

## 角色蓝图

选择 Blender 网格后自动创建蓝图：主网格的物体节点已连到生成节点。在侧栏“角色蓝图”点击 **打开角色蓝图**，与 LoyalTools 一样在独立窗口中打开，窗口只含该蓝图的节点编辑器并显示全部节点；再次点击会关闭旧窗口并重新打开。添加菜单中有六种节点：

- **物体**：选择一个网格物体。右侧输出它的全部材质槽；在“材质槽”里勾选的槽会单独输出，便于只切换主网格中的某个原部件。左侧为每个材质槽一个材质入口，未连接时自动匹配角色原材质（主网格使用“材质与部件”中的映射），匹配到的入口默认隐藏。连到生成节点的物体才会导出，参考模型不连即可。
- **材质球**：分两种。“原游戏材质”只引用已有路径（原游戏材质或工程中已有的材质实例），不暴露参数、不修改、不作为新资产打包。“材质实例”按工程中已存在的母材质新建，左侧暴露贴图参数入口（BaseColor / ID_Tex / LightMap / NomralMap 等，可增删改名，用途随参数名自动判断）；未连接的入口继承母材质。“按母材质”按母材质资料重建参数入口，并用已连接槽的 Blender 漫射图创建 BaseColor 贴图节点；“按后缀补全”为空入口找同目录 `_m`、`_n`、`_id`、`_mask` 文件并自动创建、连接贴图节点。名称必填，目录留空时保存到角色文件夹根目录。一个材质球可连接多个物体的多个槽。
- **贴图**：选择 Blender 图像或贴图文件，连接到材质实例的参数入口；同一个贴图节点可以连多个材质。UE 名称取文件名（空格等字符换成下划线），目录留空时同样导入角色文件夹根目录。压缩与 sRGB 由所连参数决定，连到用途不同的参数会报错。
- **物体切换**：与 LoyalTools 相同，每个入口是一个选项，空入口代表全部隐藏；备注、变量名、按键（HT 格式，如 `alt 6`）、选项数量和初始选项。发送后显示 HT 槽号串，例如 `2,3+4`（逗号表示末尾追加全部隐藏）。一个空选项可放在任意位置；多个空选项暂不能转换为 HT 格式。
- **群组**：把多个物体或切换放在一起，可接入切换或生成节点；“查看递归解析预览”在 3D 视图局部显示其中的物体。
- **生成**：连接的内容合并为一个骨骼网格。按钮包含发送到 UE、校验和槽位表。

没有任何面的材质槽（例如分离物体时带过来的原物体槽）一律忽略：不显示材质入口、不需要材质、不导入 UE；主网格同样适用。空槽的部件身份和映射会保留，给它重新分配面后自动恢复，原有连线也保留。

3D 视图右键菜单提供 **NTE：加入蓝图（常驻）** 与 **NTE：创建物体切换**（按名称末尾编号排序）。发送时，分离物体在临时副本中合并：主网格的槽按原顺序在前，其他物体按加入蓝图的顺序追加，同名形态键合并。各物体须绑定同一骨架，UV 层与颜色属性名称须与主网格一致，除骨架外的修改器仍需先处理。v0.3 的旧节点图打开时自动升级为新节点，并保留原有连线。

## 安装和首次设置

1. 在 Blender 4.5.7 的偏好设置中使用“从磁盘安装”，选择本地构建的 NTE Bridge 安装 ZIP，启用 **NTE Bridge / 异环桥接**。当前按作者要求仅更新仓库 main；新版安装 ZIP 在本地构建，不发布新的 GitHub Release。
2. 在 3D 视图侧栏打开 **NTE Bridge**，填写解包角色文件夹并扫描。如果资料包含多个骨骼网格，选中本次替换的原网格。三个 UE 资源路径根据 JSON 自动获取。
3. 选择 Blender 中的角色网格，插件识别绑定骨架并整理独立材质槽。在“材质与部件”中检查映射：明确匹配的名称自动填入，新增部件或存在歧义的槽从角色材质目录中选择。
4. 需要替换贴图时再展开对应区域，填写本次替换的图片、目标路径和用途。扫描到的原贴图只是资料，不会自动全部加入打包清单。
5. 选择目标 `.uproject`，点击 **发送到 UE**。默认无需手动打开 UE：插件导出当前网格后启动 UE 后台进程，在原游戏路径创建目录、导入网格和替换贴图、设置材质槽，保存后退出。UE 安装目录根据工程关联自动识别；无法确定时在高级设置指定。
6. 在“烘焙与打包”核对 UE 角色目录，保存并关闭目标 UE 工程，点击 **烘焙角色文件夹**。默认跟随当前角色；需要其他角色时，勾选“自定义 UE 烘焙目录”，点击“选择工程中的角色文件夹”浏览工程的 Content 目录。插件自动转换 UE 路径，无需手打。烘焙现有 UE 资产无需重新发送 Blender 网格。
7. 打开 Blender 中的资产选择窗口，勾选需要的网格、贴图、自定义材质实例或蓝图，设置导出位置、Mod 成品输出目录和名称，点击 **导出所选资产并打包**。首次使用不勾选；之后自动记住勾选、Mod 目录和名称，重新打开 .blend 或重新烘焙后恢复。打包不会再次烘焙，窗口在成功后关闭，失败时保留以便重试。外部打包器自动识别失败时，在高级设置指定。

发送、烘焙和打包期间显示当前阶段与已用时间；有实际文件数量或打包器进度时显示进度条。主面板按角色、材质、贴图、节点、发送与打包分区，打包单独折叠。三条 UE 原始路径、工具目录、独立导出与最近任务操作集中在高级区域；原有手动资源配置仍可使用。

在 **高级设置 → 缓存目录** 选择一个文件夹，例如 `D:\NTEBridgeCache`。重复操作复用固定位置：

- 导出及发送使用 `Jobs/current`，每次替换 FBX、贴图副本、清单、日志和报告，并移除上次不再使用的文件。
- 同一 UE 工程共用 `Cooks/<工程名_路径标识>/cooked/Windows`。不同角色都保留在这一棵 UE 目录树中；选择角色只决定本次烘焙范围和资产列表的默认筛选，不复制整份烘焙输出。
- 打包偏好自动写入缓存的 `Settings`，按 .blend、UE 工程和角色区分；不用为保留这些选择而保存模型。
- 打包仅校验本次所选资产的内容和旁文件；增量烘焙整理结果时复用未变文件的校验值，所选文件在导出前仍完整校验。
- 选择清单和打包暂存复用固定目录；重选资产会清除旧暂存。任务身份保存在报告内容中，不再用新建 UUID 文件夹记录每次操作。
- 后台 UE 的日志写入缓存中的固定文件，覆盖上次内容，不生成带日期的日志备份。

烘焙使用 UE 原生 `-iterate`，由 UE 判断哪些资产需要更新、删除或保留。工程全局烘焙设置变化时，UE 仍可能要求重新烘焙。烘焙中途失败会使旧选择失效，需要成功重烘焙后再打包；插件不保留整份 cooked 备份。下方路径显示实际位置，不必分别填写。缓存目录随 `.blend` 保存；切换缓存根目录不会自动移动或删除旧根目录的内容。

缓存目录留空时，优先使用非 C 盘 UE 工程的 `Saved/NTEBridgeCache`，其次为已保存 `.blend` 同目录的 `NTEBridgeCache`，最后为解包角色文件夹的上级目录下的 `NTEBridgeCache`。无法确定时提示选择目录，不会回退到 C 盘 AppData、用户主目录或系统临时目录。未保存 `.blend` 可以选择绝对路径；`//` 相对路径需要先保存。旧版默认 C 盘任务位置会改用新规则。成品输出仍由“Mod 输出目录”单独控制。

扫描只读取解包资料，不改写它们。识别依据是 JSON 中的完整包路径和对象引用，不以本地文件夹名猜测 `/Game/...`。角色使用的共享材质可以位于其他游戏路径。这里的“母材质”包括原游戏的材质实例，例如 `Ml_player_078_Nitsa_01`；无需补齐它更底层的 Parent JSON 就可选择其原路径。更底层父级的可用资料单独记录，不声称从实例还原完整着色器。已有手动槽映射和部件标识在重新扫描时保留。

漫射预览取自当前生效材质输出所连接的图片，不会把法线或未连接的图片当作漫射。贴图按角色材质 JSON 中的引用导入完整游戏原路径；“预览”只代表默认不打包，不改变 UE 资产位置。路径不明确时需要补充映射，不会另建一个虚构的贴图路径。桥接只补充空白占位材质或更新自己管理的预览节点；已有自定义材质图和材质实例保留并在报告中说明。这个基础颜色预览不等于复原游戏原着色器。

首次应用或切换角色资料会自动开启缺失原材质、Skeleton、PhysicsAsset 的占位创建，并放到各自对应路径；已存在的引用资产会复用并校验。占位不进入最终打包，也不能复现游戏定制材质的预览。高级设置可关闭自动占位；同角色重新读取会保留该选择，旧手动配置仍按原设置执行。

启用中的非 Armature 修改器会阻止导出。需要影响最终几何的修改应先按你的形态键工作流程处理，再导出；插件不会悄悄忽略镜像、细分等效果，也不会为应用修改器而丢弃形态键。

## 同步和打包

后台导入会为本次 UE 进程自动启用 **Python Editor Script Plugin**、**Editor Scripting Utilities**、**Geometry Script**（核验 UV）和 **Control Rig**（只读检查骨骼层级），无需预先打开 UE 配置插件，也不会改写 `.uproject` 的插件设置。即使工程中这些插件原先关闭，后台进程仍能加载它们；引擎安装本体需包含这些内置插件。

发送到已经打开的编辑器时，该编辑器需已启用上述插件并重启，在项目设置的 Python 中开启本机远程执行。缺少插件会在修改资产前给出中文说明，也可以关闭目标工程后改用后台导入。插件会核对完整工程路径；不会选择列表中的第一个编辑器。

**发送到 UE** 会在后台依次导出当前模型和导入目标工程，自动使用本次新生成的文件。任务目录中的 `ue_report.json` 记录实际槽号、形态键、资产路径和错误。默认“后台导入（无需打开 UE）”要求目标工程的编辑器已关闭，并自动启动后台 UE 完成导入后退出；也可选择同步到已打开的 UE。高级区域仍提供单独导出和发送已有任务，供排查或重复导入使用。

烘焙和打包是独立操作。烘焙针对已保存的 UE 角色文件夹，要求目标工程已关闭；其他工程不受影响。资产窗口读取本次烘焙的真实资产类型及文件清单，显示名称、路径、类型和大小，支持搜索与筛选。默认只显示角色目录，“显示目录外依赖”可查看共享资产；全选/全不选仅影响当前筛选结果，已经勾选但暂时隐藏的项目仍计入导出。Material、Skeleton、PhysicsAsset 和已识别的原角色材质引用不能勾选；已有自定义材质实例、动画蓝图和普通蓝图可以选择。未选中的依赖不会自动加入 Mod。

原材质实例的识别依靠已读取的角色资料。改选尚未读取资料的其他角色目录时，插件只能确认实际资产类型，无法仅凭 `MI` 名称区分原游戏材质实例与自定义实例；请只勾选需要随 Mod 提供的实例。

“烘焙资产导出目录”默认使用 `D:\Neverness to Everness Mod Loader\cook\packager\xg\HT\Content\Characters`。角色文件夹直接放在这里：例如 `/Game/Characters/Player/078_Nitsa/SM_Nitsa` 导出为 `Characters/078_Nitsa/SM_Nitsa.uasset`，省去角色上方的 `Player` 层。角色内部子目录和 `.uexp/.ubulk/.uptnl` 文件保留。目录外共享资产仍使用同一 `Content` 根下的原相对位置。成品 `.pak/.utoc/.ucas` 使用单独的 Mod 输出目录。

导出后自动调用现有外部打包器的 Morph 修复、retoc 转换和验证服务。打包使用所选文件的独立副本，并按 UE 原始包路径建立容器，使角色导出目录的整理不改变游戏资产引用。每次先检查所选文件和路径，再删除该角色上次的导出文件夹，只重新导出本次勾选资产；其他角色保留。最终 Mod 也仅包含本次所选资产。选择绑定本次烘焙报告和文件指纹；重新烘焙后恢复仍可打包的原勾选。若在 UE 中继续修改角色，请保存后重新烘焙，再选择最新资产。

外部打包器目录需包含 `NteMorphTargetPatch.exe`、`retoc.exe`、`oo2core_9_win64.dll`，并安装 .NET 8 Runtime。开发源码方式首次构建适配器另需 .NET 8 SDK 和打包器源码；发布 ZIP 会包含已编译适配器，不携带外部工具本体。

同一输出目录、同一 Mod 名称会覆盖上次的 `.pak/.utoc/.ucas`。新成品全部生成并通过校验后才替换；打包失败保留旧成品，替换发生 I/O 错误时恢复旧文件。正常完成后清除替换临时文件，不累计成品备份。不同名称的 Mod 保持独立。

## 命令行

使用普通 Python 3.11+ 或 UE 自带 Python。`python` 在部分 Windows 环境中只是应用商店占位符，需使用实际解释器路径。

```powershell
& '<Python.exe>' blender_addon/nte_bridge/cli.py validate --manifest '<任务目录>/manifest.json'
& '<Python.exe>' blender_addon/nte_bridge/cli.py sync --manifest '<任务目录>/manifest.json' --engine-dir '<UE_5.6目录>' --mode commandlet
& '<Python.exe>' blender_addon/nte_bridge/cli.py cook --request '<缓存中的烘焙请求.json>' --engine-dir '<UE_5.6目录>' --report '<烘焙报告.json>'
& '<Python.exe>' blender_addon/nte_bridge/cli.py package-selection --selection '<资产选择.json>' --packager-source '<外部打包器目录>' --output-dir '<成品目录>' --mod-name 'MyCharacter_P'
```

## 开发与验证

```powershell
& '<Python.exe>' -m unittest discover -s tests -p 'test_*.py' -v
& '<Python.exe>' tools/create_test_project.py
& '<Blender.exe>' --background --factory-startup --disable-autoexec --python-exit-code 1 --python tests/blender_smoke.py
& '<Python.exe>' tools/build_release.py
```

Blender 测试的 `artifacts/blender_smoke/result.json` 给出生成的清单路径。使用该路径运行上面的 `cli.py sync --mode commandlet`，即可在测试工程验证实际 UE 导入。`tests/unreal_smoke.py` 进一步验证同任务重导入，输入由环境变量 `NTE_BRIDGE_SMOKE_MANIFEST` 指定，并拒绝在其他工程执行。

测试使用 `artifacts/` 内的独立工程和合成模型，不要求重导入作者的实际游戏资产。适配器构建见 [tools/packager_cli/README.md](tools/packager_cli/README.md)，发布打包前必须先构建它。实际测试记录见 [docs/VALIDATION.md](docs/VALIDATION.md)。任务协议见 [docs/CONTRACT.md](docs/CONTRACT.md)。

## 边界

- 当前只支持一个网格、一个单根骨架；资产名称使用 ASCII 字母、数字和下划线。
- 新的材质实例创建、自定义多槽材质状态、UE 切换/面板自动生成、按住生效和条件链仍待实现。
- 保留形态键不等于提供游戏内形态键滑块。
- 占位材质用于路径和引用，不能复现游戏定制着色器的完整编辑器预览。
- 导入失败可能留下已创建或变更的编辑器资产；报告列出部分变更，不声称完整回滚。固定日志和结果记录最近一次操作；失败状态不会复用旧成功报告。
- 游戏中的最终纹理显示、形态键与骨骼表现仍需使用实际角色验证。自动检查与容器验证不能代替游戏运行验证。
